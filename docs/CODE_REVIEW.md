## Архитектурные проблемы, требующие следующих этапов

### P0: God Objects

- `mainwindow.cpp` содержит более 4000 строк и совмещает login/session, SQL,
  UDP, filesystem, настройку UI, CRUD всех медицинских модулей и отчеты.
- `mainwindow.h:25-89` включает почти все экраны и модели проекта.
- `dialog_patient.cpp` содержит более 2200 строк и совмещает данные пациента,
  учет, документы, комментарии, печать и валидацию.
- `dialog_reports.cpp` содержит SQL, агрегации и HTML-рендеринг в одном классе.

**Рекомендация:** выделять coordinators/services/repositories по одному read-only
сценарию, затем переносить команды изменения данных в транзакционные services.

### P0: SQL находится непосредственно в UI

Найдено более 300 `query.exec(...)`; значительная часть запросов строится
конкатенацией строк. Помимо injection это приводит к ошибкам кавычек, дат,
локали и отсутствию единообразной обработки ошибок.

**Рекомендация:** ввести repositories и обязательный `prepare/bindValue`.
Сначала мигрировать auth, patient search, patient card, затем остальные модули.

### P1: глобальное изменяемое состояние

Старый `Objects_app` создавался локально около 100 раз, хотя все его поля были
static. Это скрывает зависимости и мешает тестированию. В текущем срезе данные
перенесены в `ApplicationContext`, `UserSession` и `ApplicationPaths`.
Совместимый alias оставлен только для поэтапной миграции.

### P1: QObject ownership

В проекте много `new` без parent: модели, диалоги, `QSettings`, сокеты и
вспомогательные widgets. Некоторые объекты передаются Qt layout/view и получают
владельца, но значительная часть имеет неочевидное время жизни.

**Рекомендация:** parent для QObject, стек для модальных диалогов, RAII для
не-QObject. Запретить `deleteLater()` для стековых объектов.

### P1: потоки и подключения БД

`thread_load_data` и старые thread-классы требуют отдельной проверки: Qt SQL
connection должен создаваться и уничтожаться в том потоке, где используется.
Нельзя передавать активный `QSqlDatabase/QSqlQuery` между потоками.

### P1: хранение паролей

Приложение сравнивает MD5 пароля (`src/ui/auth/dialog_login.cpp:225-235`). MD5
не подходит для хранения паролей.

**Рекомендация:** серверная миграция на Argon2id или bcrypt с индивидуальной
солью. Это изменение требует совместной миграции схемы и клиентов, поэтому не
включено в совместимый рефакторинг.

### P2: сборка и тесты

- `.pro` содержит длинный плоский список файлов.
- Автоматических Qt-тестов не обнаружено.
- В корне есть не подключенные к сборке старые файлы: `dialog.cpp`,
  `dialog_added_patient_info.*`, `add_invalid_patient.*`.
- Компилятор все еще сообщает deprecated API и unused variables.
