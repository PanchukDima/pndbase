# Полная PostgreSQL-схема pndbase

`database/deploy.sql` восстанавливает схему PostgreSQL по фактическим SQL-контрактам C++/Qt-приложения. При реконструкции учитывались не только имена объектов после `FROM`/`INTO`/`UPDATE`, но и:

- все явно квалифицированные ссылки вида `table.column`;
- списки колонок каждого `INSERT`;
- колонки в `UPDATE ... SET`;
- колонки `SELECT`, `WHERE`, `JOIN`, `ORDER BY`, `GROUP BY` и оконных выражений;
- строковые фильтры `QSqlTableModel::setFilter`;
- все цели `QSqlTableModel::setTable`;
- ключевые и отображаемые колонки `QSqlRelation`;
- индексный доступ через `query.value(n)` и `model()->index(row, n)`;
- реальный порядок и типы 34 аргументов `insert_all_info(...)`.

C++-исходники при восстановлении не изменялись.

## Требования и развертывание

Рекомендуется PostgreSQL 12 или новее и новая пустая база:

```bash
createdb -U postgres pndbase
psql -v ON_ERROR_STOP=1 -U postgres -d pndbase -f database/deploy.sql
```

Приложение передает даты и время строками `DD.MM.YYYY` и `DD.MM.YYYY HH24:MI:SS`. `deploy.sql` устанавливает `DateStyle` для собственного сеанса, но для последующих подключений Qt настройку следует закрепить на уровне базы:

```sql
ALTER DATABASE pndbase SET DateStyle TO 'ISO, DMY';
```

Сценарий выполняется в одной транзакции и создает схемы:

- `public` для `patients_find` и `insert_all_info`;
- `test` для основной медицинской части;
- `library` для справочников;
- `messager` для чата;
- `reports_library` для отчетных справочников и представлений;
- `logs` для ошибок приложения.

`CREATE TABLE IF NOT EXISTS` делает повторный запуск безопасным для уже совместимой структуры, но не превращает сценарий в миграцию. Для несовместимой старой базы требуется отдельная миграция после резервного копирования.

## `test.rights`

Приложение выполняет:

```sql
SELECT rights.rights
FROM test.rights, test.staff, test.users
WHERE staff.id = users.staff_id
  AND users.id = rights.user_id
  AND staff.status = '0'
  AND staff.id = ...
```

Затем C++ перебирает результат посимвольно и распознает символы `0` и `1`. Поэтому контракт таблицы задан явно:

- `id bigint`;
- `user_id bigint UNIQUE REFERENCES test.users(id)`;
- `rights text NOT NULL DEFAULT ''`.

Bootstrap-пользователь получает строку из 64 единиц.

## Автоматическая проверка покрытия

Для проверки был построен нормализованный инвентарь прямых SQL-вызовов из C++ с восстановлением строк, разорванных конкатенацией. Проверка сопоставляла исходники с DDL на уровне объектов и колонок.

Проверенный объем:

- 318 прямых SQL-вызовов;
- 99 разрешенных квалифицированных ссылок `table.column`;
- 98 вхождений `INSERT` со списками колонок;
- 56 `UPDATE` с извлеченными колонками `SET`;
- 26 целей `setTable`;
- 5 уникальных контрактов `QSqlRelation`;
- 2 вызова `insert_all_info`, оба по 34 аргумента.

Итоговые проверки:

1. Каждая извлеченная таблица/представление существует в DDL.
2. Каждая квалифицированная колонка существует в соответствующем объекте.
3. Каждая колонка каждого списка `INSERT` существует в целевой таблице.
4. Каждая извлеченная колонка `UPDATE ... SET` существует в целевой таблице.
5. Все цели `setTable` существуют.
6. Все key/display-колонки `QSqlRelation` существуют.
7. Арность функции совпадает с обеими точками вызова.

Внешний SQL Server-запрос к `[EMSRN_Load].[dbo]...` исключен из PostgreSQL deployment, поскольку он выполняется через отдельное подключение в `other_db/emsrn`.

## Известные дефекты SQL в C++

Следующие ошибки находятся в исходных строках приложения и не исправляются DDL:

- `INSERT INTO messager.group_messages(group_id, staff_add_id, message,)` содержит лишнюю запятую.
- Один `INSERT` диагноза помещает `first='...'` внутрь `VALUES` вместо передачи значения.
- Один фильтр посещений оканчивается незавершенным `AND`.
- Некоторые отчетные ветви читают `query.value(1)` после `SELECT` одной колонки.
- Ряд запросов собирается конкатенацией пользовательских строк без bind-параметров.

Также имена `test."end"` и `messager."group"` заключены в кавычки в DDL, поскольку совпадают с SQL-ключевыми словами. Qt-модели обычно экранируют имя объекта самостоятельно. Прямой запрос приложения к `test.end` следует отдельно проверить на используемой версии драйвера QPSQL.

## Границы реконструкции

Исходный дамп PostgreSQL отсутствует, поэтому ограничения, индексы, типы и defaults восстановлены из поведения клиента. Схема покрывает все найденные SQL-контракты проекта, но перед импортом производственных данных рекомендуется сравнить ее с резервной копией существующей базы и проверить на копии данных все отчеты, фильтры и формы редактирования.
